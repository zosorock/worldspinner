# B-003: Globe Does Not Spin 360° + Random on Each Spin After First

## Summary

The globe does not complete a full 360° rotation plus random additional rotation on each spin after the first spin. Instead, it animates to absolute rotation values, causing backwards rotations or incomplete cycles. This is a **critical violation** of US-008 Acceptance Criteria #1.

## Task Classification

- **Type**: Bug (Critical)
- **Component**: Globe Spin Animation (`App.jsx`, `spinAnimation.js`)
- **Priority**: Critical
- **Status**: In Progress
- **Parent Story**: US-008
- **Owner**: Developer

## Current Behavior

Framer Motion's `animate()` function interprets `{ rotate: totalDegrees }` as an **absolute target** value. Each spin calculates a fresh random value between 360-720°, then animates TO that absolute position regardless of where the globe currently is.

**Example rotation sequence (demonstrating the bug):**

| Spin | Current Position | calculateSpinRotation() | Animation Target | Actual Movement |
|------|------------------|-------------------------|------------------|-----------------|
| 1    | 0°               | 540°                    | 540°             | +540° ✓         |
| 2    | 540°             | 450°                    | 450°             | **-90°** ✗ (backwards!) |
| 3    | 450°             | 680°                    | 680°             | +230° ✗ (under 360°) |
| 4    | 680°             | 400°                    | 400°             | **-280°** ✗ (backwards!) |

## Expected Behavior

Each spin should rotate the globe exactly **360° + random(0-360°)** in the **forward direction** FROM its current position, regardless of how many times it has been spun. The globe should:

1. Always rotate forward (clockwise)
2. Always complete at least one full 360° rotation
3. Accumulate rotation across multiple spins
4. Never rotate backwards

## Evidence

**HG Feedback**: "it is not spinning 360+rand(360)"

**Code Analysis** (verified 2025-12-28):
- `App.jsx:180` - Animation uses absolute target: `animate('.spinning-globe', { rotate: totalDegrees }, ...)`
- `spinAnimation.js:30` - Returns absolute value: `totalDegrees = phase1Degrees + phase2Degrees`
- No `useRef` or state variable tracks cumulative rotation between spins
- First spin works correctly (0° → 360-720°), bug manifests on subsequent spins

## Root Cause

Framer Motion's `animate()` function animates **TO** an absolute value, not **BY** a relative amount.

**Location**: `app/src/App.jsx:180`
```javascript
// BUG: This animates TO totalDegrees, not BY totalDegrees
await animate('.spinning-globe', { rotate: totalDegrees }, { duration: duration / 1000, ease: 'easeOut' });
```

**Location**: `app/src/utils/spinAnimation.js:22-40`
```javascript
// Returns absolute value (360-720), unaware of current rotation state
const calculateSpinRotation = () => {
  const phase1Degrees = 360;
  const phase2Degrees = Math.floor(Math.random() * 360);
  const totalDegrees = phase1Degrees + phase2Degrees;  // Absolute, not cumulative
  const duration = 6000;
  return { totalDegrees, duration };
};
```

## Suggested Fix Approaches

### Option A: Cumulative Tracking with useRef (Recommended)

Track cumulative rotation in a ref, add each spin's amount to it:

```javascript
// Add ref to track cumulative rotation
const cumulativeRotationRef = useRef(0);

// In spinGlobe():
const { totalDegrees: spinAmount, duration } = calculateSpinRotation();
cumulativeRotationRef.current += spinAmount;  // Add to cumulative
await animate('.spinning-globe', { rotate: cumulativeRotationRef.current }, {
  duration: duration / 1000,
  ease: 'easeOut'
});
```

**Pros**: Simple, follows existing useRef patterns in codebase, no changes to spinAnimation.js
**Cons**: Cumulative value grows unbounded (but CSS handles large rotation values fine)

### Option B: Reset Before Each Spin

Reset rotation to 0° before each spin, then animate to totalDegrees:

```javascript
// Reset to 0 instantly, then animate
await animate('.spinning-globe', { rotate: 0 }, { duration: 0 });
await animate('.spinning-globe', { rotate: totalDegrees }, { ... });
```

**Pros**: Simple, no state tracking needed
**Cons**: HG indicated preference for continuing from where it stopped; may cause visual "snap"

### Option C: Framer Motion Relative Syntax (Research Needed)

Research if Framer Motion supports relative value syntax:

```javascript
// Hypothetical - needs verification
await animate('.spinning-globe', { rotate: `+=${totalDegrees}` }, { ... });
```

**Pros**: Cleanest if supported
**Cons**: May not be supported by Framer Motion's imperative API
